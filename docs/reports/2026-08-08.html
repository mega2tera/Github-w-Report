1zhaoxuya520/reverse-skill

为 AI 编程代理提供逆向工程与授权安全测试的任务路由、工具检测和标准化取证流程。

本周 +10,400 ★总计 20,614 ★PowerShellMIT

它不是单一逆向工具，而是一套面向 Claude Code、Codex、Cursor 等代理的安全技能路由包。代理收到 APK、ELF、前端加密、PCAP、恶意样本或 CTF 任务后，会先确认授权范围，再按目标类型选择 jadx、Frida、Ghidra、radare2、Burp Suite 等方法和工具，并记录时间线、证据、发现与复现路径。

核心功能

  • 按 APK、iOS、二进制、.NET、JavaScript、固件、恶意代码、API 安全等场景自动选择技能流程。
  • 扫描本机工具链并生成索引，缺少工具时提供按需引导；支持 Windows、Linux、macOS 和 Kali。
  • 通过 scope、timeline、Evidence→Finding→Path 和 field journal 统一授权边界、证据链及报告输出。

解决的问题

  • 解决 AI 代理面对安全目标时不知道该选哪种工具、容易凭感觉拼命令的问题。
  • 解决不同逆向与渗透工具分散、环境状态不透明、相同错误反复发生的问题。
  • 把一次性分析经验沉淀为可复用技能和现场日志，降低后续同类案件的启动成本。

典型应用

  • 对自有或已授权 Android APK、桌面程序、共享库和固件进行静态/动态分析。
  • 分析网页参数加密、抓包重放、API/GraphQL 安全和补丁差异。
  • 组织 CTF、恶意样本、供应链/SBOM 或红队演练中的多阶段分析工作。

适合谁

  • 安全研究员、逆向工程师、渗透测试人员和 CTF 参赛者。
  • 希望让代码代理执行可审计安全流程的团队。

差异化特点

  • 重点是路由与作业规范，而不是重复实现 jadx、Frida、IDA 等底层工具。
  • 在执行目标操作前设置授权与网络范围门禁，并把取证记录纳入流程。

限制与风险

  • 只能用于自有资产、明确授权测试、CTF 或合法研究；路由包不会替代人工确认授权范围。
  • 依赖 Java、Node.js、Python 及多种第三方工具，不同平台的可用能力并不完全一致。
  • 仓库主体为 MIT，但内含或调用的组件可能采用 GPLv3、AGPL 等其他许可证。

应用潜力

  • 可作为团队安全代理的统一入口和作业手册。
  • 适合将资深分析人员的方法、证据要求和复盘经验固化为可执行流程。

快速开始

克隆仓库后运行对应平台的 refresh-tool-index 脚本生成工具索引，再从 MASTER-ROUTING 或 master-route.ps1 输入任务并创建案件目录。

成熟度判断

场景覆盖面很广并已有 v1.0 发布，但大量能力依赖外部安全工具及其本机配置，实际效果取决于代理、环境和具体目标。

典型应用

  • 教师选择单元作为课堂材料、实验作业和课前课后测验。

适合谁

  • 多语言、可在 Codespaces/Binder 或本地运行，教学复用成本低。

  • 不系统覆盖经典机器学习、企业业务案例、云平台工程和深层数学推导。
  • 课程强调基础教育，不等同于生产级模型部署或 MLOps 指南。

应用潜力

  • 可直接改造成学校课程、企业入门训练营或个人 12 周学习计划。
  • 为后续学习生成式 AI、计算机视觉或 NLP 提供统一概念基础。

快速开始

Fork 或克隆仓库，先完成环境配置课；完全新手可先运行 Hello AI World、简单神经网络、图像分类和文本情感四个示例。

3TencentCloud/TencentDB-Agent-Memory

面向 Agent 团队的记忆中枢，把对话、文档和代码加工成可治理、可共享、可装配的记忆资产。

本周 +7,501 ★总计 17,580 ★TypeScriptNOASSERTION

系统将信息分成 Chat Memory、Skill、Wiki 和 CodeGraph 四类资产：对话被逐层提炼为事实、场景和长期画像；成功工作流可沉淀为带版本和验证规则的技能；文档转为带链接图的 Wiki；代码转为符号、调用关系和影响路径。团队可按 private、team、restricted 和 agent 范围控制资产并绑定给不同代理。

核心功能

  • L0 原始对话到 L3 Persona 的分层记忆，以及 BM25、向量检索和 RRF 组合召回。
  • 从对话与工具调用提取技能，管理版本、资源、触发边界、执行步骤和验证规则。
  • 构建文档 Wiki 与代码 CodeGraph，支持调用关系和修改影响分析。
  • 提供团队、角色、所有者、ACL、资产审核和 Agent 装配面板。

解决的问题

  • 解决换会话或换代理后反复解释项目背景、偏好和历史决策的问题。
  • 解决多个代理重复阅读同一批文档和代码、重复探索已验证流程的问题。
  • 补足普通 RAG 缺少资产版本、所有权、共享边界和按代理装配的问题。

典型应用

  • 为编码代理保存架构决策、历史事故、代码调用图和发布检查技能。
  • 给研究、开发、测试等不同角色装配不同的团队知识与工作流。
  • 导入旧对话、现有文档和代码库，让新代理直接继承已有经验。

适合谁

  • 同时使用多个 AI Agent 的研发团队和个人工作室。
  • 需要长期记忆、知识治理及权限隔离的 Agent 平台开发者。

差异化特点

  • 管理的是可复用资产而非单纯聊天记录或向量分块。
  • 同时覆盖对话、技能、文档关系和代码调用图，并允许跨代理框架迁移。

限制与风险

  • Wiki 和 CodeGraph 需要异步构建，导入后不能立即全部可用。
  • 私有仓库与 SSH 凭据支持仍在完善，自动记忆路由尚未完全成熟。
  • 部署包含多个服务并需要配置模型参数，运维复杂度高于轻量记忆库。

应用潜力

  • 可成为企业内部 Agent 的团队知识与技能控制平面。
  • 适合将项目经验从个人会话提升为可审计、可授权、可迁移的组织资产。

快速开始

使用 deploy/global-images 的一键脚本启动 memory-core、memory-hub 和 proxy，配置记忆组与代理组模型参数后在 8125 端口打开管理面板。

成熟度判断

Team Memory 仍处于快速演进的 Beta；已有完整服务、面板、SDK、迁移工具和基准，但路由自动化与部分仓库接入仍在完善。

5lyogavin/airllm

通过逐层加载模型，把 70B 乃至 405B 模型的推理显存门槛降到单张消费级 GPU。

本周 +5,521 ★总计 29,937 ★Jupyter NotebookApache-2.0

AirLLM 将 Transformer 模型按层切分，推理时只把当前计算层加载到 GPU，完成后释放并换入下一层，从而避免整模型常驻显存。它支持 Hugging Face 模型、本地模型、CPU/Mac、预取和压缩，也可配合 8/4 位量化；核心取舍是用存储与数据传输时间换显存。

核心功能

  • 70B 模型可在约 4GB GPU 上运行，405B Llama 3.1 可在约 8GB 显存环境尝试。
  • 无需必须进行量化、蒸馏或剪枝即可执行超大模型推理。
  • 支持 Llama、Qwen、ChatGLM、Baichuan、Mistral、InternLM、Mixtral 等模型及 CPU/macOS。
  • 通过分层切片、压缩和预取降低峰值内存并部分隐藏 I/O 延迟。

解决的问题

  • 解决研究者只有小显存设备却需要验证超大模型能否运行的问题。
  • 避免为了单次实验购买多卡服务器或先进行破坏精度的模型压缩。

典型应用

  • 在消费级 GPU 上做低吞吐的超大模型功能验证与研究。
  • 离线执行批量不敏感、对响应延迟要求不高的生成任务。
  • 比较量化前后的模型行为，或在 Mac/CPU 环境做兼容性实验。

适合谁

  • 显存有限的 LLM 研究者、学生和个人开发者。
  • 需要先验证大模型再决定云端或多卡投入的团队。

差异化特点

  • 优化重点是极低显存可运行，而不是高吞吐服务。
  • 可在不量化原始权重的情况下工作，保留模型精度路径。

限制与风险

  • 每层反复从内存或磁盘搬运会显著降低生成速度，存储和总系统内存仍需容纳模型。
  • 低显存可运行不等于可高并发服务，长上下文和大批量会进一步放大延迟。
  • 新模型架构是否兼容需要逐一验证。

应用潜力

  • 降低超大模型教学、研究和功能验证的硬件门槛。
  • 可用于边缘设备上的低频大模型任务或作为模型选型验证工具。

快速开始

安装 airllm，使用 AutoModel.from_pretrained 指定 Hugging Face 仓库或本地模型路径，再像 Transformers 模型一样完成分词和生成。

成熟度判断

已支持多种主流模型并提供 Notebook，但属于专门的内存换时间方案，不适合直接替代高性能推理引擎。

6esengine/DeepSeek-Reasonix

专门围绕 DeepSeek 前缀缓存机制设计的终端编程代理，用稳定缓存降低长会话成本。

本周 +4,739 ★总计 32,929 ★GoMIT

Reasonix 不追求多模型兼容，而是让系统提示、工具定义和对话前缀尽量保持字节稳定，提高 DeepSeek 缓存命中率。它提供持久工作区会话、计划模式、MCP、技能、记忆、生命周期 Hook、权限白名单、网页搜索、语义索引和 Web 仪表盘，并对异常工具调用进行修复。

核心功能

  • 缓存优先代理循环，维持稳定前缀并展示缓存命中率和成本。
  • 支持 MCP、技能、项目/用户记忆、PreToolUse/PostToolUse Hook 和工作区命令权限。
  • 持久会话、计划模式、可配置搜索引擎、本地或兼容接口的语义索引。
  • 终端为主，并提供仪表盘查看会话、成本和执行状态。

解决的问题

  • 解决通用编程代理在长会话中频繁破坏 DeepSeek 前缀缓存、重复计费的问题。
  • 修复 DeepSeek 工具调用格式异常，提升长时间自主运行的稳定性。
  • 把权限、搜索、技能、记忆和项目索引整合到同一终端代理。

典型应用

  • 长时间运行代码检索、缺陷修复、重构和测试任务。
  • 对 API 成本敏感、愿意固定使用 DeepSeek 的开发团队。
  • 通过 MCP 和 Hook 接入内部工具，并用命令白名单控制执行范围。

适合谁

  • 主要使用 DeepSeek API 的终端开发者。
  • 重视长会话缓存成本和可观测性的代理工具研究者。

差异化特点

  • DeepSeek-only 是架构选择，整个循环围绕其字节级前缀缓存优化。
  • 同时处理缓存稳定、工具调用修复和成本控制，而不是只提供通用聊天壳。

限制与风险

  • 只支持 DeepSeek，需要付费 API Key；不适用于离线或多供应商切换。
  • 终端优先，不提供 Cursor 式完整 IDE 编辑体验。
  • 最困难的推理任务未必优于更高端模型，缓存案例不能直接代表所有工作负载。

应用潜力

  • 适合发展为低成本、长运行的软件工程代理。
  • 其缓存稳定设计可为其他具备显式前缀缓存的代理架构提供参考。

快速开始

安装后在 ~/.reasonix/config.json 配置 DeepSeek API，并可在项目 .reasonix 目录增加 MCP、权限、技能和记忆覆盖配置。

成熟度判断

发布迭代活跃并有基准与案例，但项目变化快；真实成本收益取决于任务结构、缓存定价和命中率。

7virgiliojr94/book-to-skill

把技术书、文档目录或多份资料加工成代理可按需调用的结构化技能，而非一次性摘要。

本周 +3,957 ★总计 18,391 ★PythonMIT
